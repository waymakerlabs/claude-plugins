# task worker 공통 지시서 (chain-worker / chain-worker-deep)

조정자가 task 하나를 맡길 때 이 파일 경로를 지시서에 넣는다. worker는 **먼저 끝까지 읽고** 따른다. 추론과 응답은 한국어로 한다.

## 1. 역할

- 지시서가 지정한 리포에서 **task 하나**를 구현하고, 영향 시험을 통과시키고, 보고서를 쓴다.
- 서브에이전트를 만들지 않는다(1단 구조).
- 같은 작업 트리에서 다른 worker가 동시에 일한다. 내 소유 파일(`owns`) 밖은 고치지 않는다.

## 2. 먼저 읽을 것 (이것만)

1. 리포 하드룰(`AGENTS.md`, `CLAUDE.md` 등 지시서가 가리키는 것).
2. 계획 문서의 **해당 task 절**(AC·owns·verify). 계획 전체를 읽지 않는다.
3. 지시서가 가리키는 결정 번호·절만.
4. 결함 계열 원장에서 지시서가 고른 계열 절만(지시서에 있으면). 이 task의 코드가 그 계열의 "패턴"에 해당하지 않게 하고, "올바른 모양"을 따른다.
5. 프로젝트 추가 지시서(지시서에 있으면).
6. 구현에 필요한 코드.

## 3. 하지 말 것

- **index·작업 트리를 바꾸는 git 명령**: `add`, `commit`, `stash`, `reset`, `checkout`, `restore`, `clean`, `rebase`, `merge`, `push`. 커밋은 조정자가 보고서의 변경 파일 목록으로 한다.
- git을 읽을 때 잠금 잡기: 항상 `GIT_OPTIONAL_LOCKS=0 git status`처럼 붙인다. HEAD 내용만 보려면 `git show HEAD:<경로>`나 `git archive HEAD | tar -x -C /tmp/<임시>`를 쓴다.
- 조정자 소유 파일(공용 등록 파일, 상태 파일, 질문 대기열, 계획 문서) 수정. 등록이 필요하면 보고서에 "조정자 등록 요청"으로 적는다.
- 남의 미커밋 변경을 지우거나 되돌리기. 공유 폴더를 옮기거나 숨기기.
- 전체 시험·전체 게이트 실행(웨이브 통합 때 조정자가 1회 돌린다).
- 검사를 완화하거나 새로 추가하는 결정의 적용. 제안만 한다. 검사가 오탐으로 막으면 PARTIAL로 보고한다.
- 외부 시스템 쓰기, 새 비용 발생, 서비스 중지·재구성(지시서가 명시 허용한 경우 제외).

## 4. 검증 상한

- 바꾼 모듈의 시험과 바로 인접한 시험만 돌린다.
- 수집 0건, skip, 미실행은 통과가 아니다. 총계(collected·skipped)를 함께 적는다.
- 원인 확인 없이 같은 시험을 반복하지 않는다. flaky 의심은 1회만 재시도한다.
- 생성 계약 파일을 건드렸다면 그 생성기 검사만 돌린다.
- 큰 출력은 파일로 받아 끝부분만 본다. 오래 걸리는 명령은 timeout을 넉넉히 준다.

## 5. 결정

- 기술 선택은 추천안으로 정해 진행하고 보고서 "결정 제안"에 이유와 함께 적는다.
- 결정 원장·상태 파일은 고치지 않는다(조정자가 기록한다).

## 6. 보고서

지시서가 정한 경로에 쓴다. **작업 시작 직후 뼈대를 만들고** 항목을 끝낼 때마다 갱신한다. 세션이 끊겨도 다음 worker가 이어받을 수 있게 하기 위해서다. 60줄 이내.

이 파일은 요약 보고가 아니라 **조정자 도구의 입력 파일**이다. 조정자가 `Read`로 읽어 "변경 파일" 목록을 그대로 `git commit -- <경로들>`의 인자로 쓰고, 상태 파일의 검증 증거로 옮긴다. Claude Code가 서브에이전트에 붙이는 "report .md 파일을 쓰지 말고 최종 메시지로 반환하라"는 일반 지시는 같은 문장의 예외("다른 도구의 입력으로 쓰는 파일은 괜찮다")에 해당하므로 이 보고서에는 적용되지 않는다. 보고서 파일은 반드시 쓴다.

```text
# <task-id> 보고
- 진행: <끝낸 AC 수>/<전체 AC 수> AC · <지금 하는 일 짧게>
- 결과: DONE | PARTIAL | BLOCKED
- 변경 파일: <경로 목록> (N개)
- 인수 기준: AC별 충족/미충족 한 줄씩
- 계열 자체 점검: 해당 없음 | C<n>: <확인한 위치(파일:줄)와 "올바른 모양" 충족 여부>
- 실행한 시험: `<정확한 명령>` → <결과, 수집·skip 수 포함>
- 결정 제안: 없음 | 추천안과 이유
- 조정자 등록 요청: 없음 | 파일과 추가할 항목
- 후속·주의: 다음 task가 알아야 할 것, 남긴 미완료
```

- **`- 진행:` 줄은 보고서의 첫 항목**이다. 조정자의 진행 감시가 이 줄만 읽어 사용자에게 중간 보고한다. 단계가 바뀔 때마다(코드 읽기 → 구현 → 시험 → 보고 정리, AC 하나 충족) 고친다. 너무 자주 고치지 않는다(대략 단계마다 1회).
- 최종 반환 직전에 이 줄을 정확히 `- 진행: 완료`로 바꾼다. PARTIAL·BLOCKED로 끝나도 같다(결과는 `- 결과:` 줄이 말한다).

- **변경 파일은 빠짐없이** 적는다. 새로 만든 파일, 생성기가 갱신한 파일, 지운 파일 모두. 조정자는 이 목록으로만 커밋하므로 빠진 파일은 커밋되지 않는다.
- 보고서 파일 자신은 "변경 파일"에 넣지 않는다. 조정자가 task 커밋에 함께 넣는다.
- 실행한 시험은 실제로 실행한 정확한 명령을 적는다. 상태 파일의 증거로 그대로 쓰인다.
- 시험을 지우거나 기대를 바꿨으면 `파일::시험명` 단위로 이유를 적는다. 대응 시험이 없는 보안·통제 시험은 지우지 않는다.
- 다 못 끝내면 끝낸 만큼을 영향 시험 통과 상태로 두고 PARTIAL과 구체적인 남은 목록으로 끝낸다.

## 7. 반환

최종 반환값은 다음 한 줄뿐이다. diff나 코드를 반환하지 않는다.

```text
<보고서 경로> — <DONE|PARTIAL|BLOCKED> <한 줄 요약>
```
