# 집중 분석 (Focused Analysis) — 이중 독립 트랙 교차검증

> 이 문서를 열었다면 트리거가 켜졌다는 뜻이다. 절차를 기억으로 재구성하지 말고 아래 순서를 그대로
> 따른다. Orca/codex 실행 세부는 `orca-codex-delegate` skill을 그대로 따른다 — 이 문서는 그 위에
> "두 트랙을 동시에 돌리고 종합한다"는 절차만 추가한다.

## 언제 쓰는가

- **트리거**: "집중 분석해줘", "상세 분석해줘", 또는 동등하게 강조된 분석 요청.
- **트리거가 아닌 것**: 강조 없는 일반 "분석해줘"/"조사해줘" — 이건 평소처럼 처리한다(각 프로젝트
  CLAUDE.md의 서브에이전트 우선순위 규칙을 따른다). 매번 이 절차를 쓰면 사용자가 원하는 것보다 훨씬
  비싸진다.
- **적합한 대상**: "이게 정상인가 결함인가", "근본 원인이 뭔가" 처럼 **하나의 정답이 있고 잘못 판단하면
  되돌리기 어려운 실행으로 이어지는 진단성 질문**. 여러 옵션 중 선택("A안 vs B안")에는 판단 패널(여러
  관점의 병렬 평가) 쪽이 더 맞을 수 있다 — 애매하면 사용자에게 확인한다.

## 절차

### 0. Claude가 먼저 문제를 정리한다 (직접, 위임하지 않음)

두 트랙에 동일하게 먹일 자기완결적 문제 설명을 만든다 — 배경 사실(실측값·file:line 근거)·질문·이미
있는 가설(있다면). 이 단계는 오리엔테이션이므로 Claude가 직접 하고 위임하지 않는다.

### 1. 두 트랙을 동시에(같은 메시지에서) 실행한다

**트랙 A — Opus 서브에이전트**

`Agent` 도구, `model: "opus"`(사용자가 다른 모델을 명시하지 않는 한 고정), `subagent_type`은 작업
성격에 맞는 것(대개 `general-purpose`). 프롬프트에 0단계 문제 설명 전체를 포함하고, **"기존 가설에
동의만 하지 말고 완전히 독립적으로 재검증하라"**를 명시한다 — 그냥 확인만 시키면 교차검증의 의미가
없다.

**트랙 B — Orca + codex**

`orca-codex-delegate` skill의 §4 크로스체크 절차(읽기 전용)를 그대로 따른다 — Run 생성 → Task
생성(같은 문제 설명) → `orca-review` 프로필로 워커 기동 → `dispatch --inject`. **모델·effort는
명시적으로 override한다**(프로필 기본값에 맡기지 않음 — 프로필의 기본값은 다른 목적의 크로스체크와
공유되고 나중에 바뀔 수 있기 때문에, 이 skill은 자기 것을 명시적으로 고정한다):

```bash
codex --profile orca-review -m gpt-5.6-sol -c model_reasoning_effort="high"
```

⚠️ **이 값은 2026-08-13 시점 사용자가 명시적으로 지정한 값이다.** `gpt-5.6-sol`이 더 이상 유효한
모델이 아니거나(게이트웨이 모델 로테이션으로 사라짐) codex가 이 이름을 거부하면, **지어내서 대체하지
않고 사용자에게 확인한다** — 이 skill이 만들어진 계기 자체가 사용자가 부른 모델명("sol")이 codex
base config에 존재하지 않아 확인부터 거친 사례였다. 사용자가 이번 실행에서 다른 모델/effort를
명시하면 그 값으로 override한다.

### 2. 둘 다 끝날 때까지 기다린다 (barrier — 하나만 오면 종합하지 않는다)

- 트랙 A는 `Agent` 도구의 완료 알림으로 온다.
- 트랙 B는 `Monitor` 도구로 `orca orchestration check --wait`을 감싸서 기다린다 — `check --wait`은
  다중 JSON(keepalive + 마지막 실제 Delivery)을 낼 수 있으므로 파일로 받아 마지막 객체만 파싱한다
  (`orca-codex-delegate` §6 실측 함정과 동일한 패턴).
- 하나가 먼저 오면 그 결과를 요약해두되, **종합 판단은 둘 다 온 뒤에만** 내린다. 사용자가 먼저 물으면
  "한쪽만 왔고 아직 종합 전"이라고 정확히 답한다.

### 3. Claude가 종합한다

두 결과를 나란히 놓고 일치하는 지점과 불일치하는 지점을 명시적으로 구분한다.

- **일치**하면 왜 일치하는지(같은 근거를 봤는지, 독립적으로 같은 결론에 도달했는지)를 한 줄 덧붙이고
  그 판단으로 진행한다.
- **불일치**하면 그 자체를 사용자에게 그대로 보여준다 — 둘 중 하나를 조용히 고르지 않는다. 필요하면
  추가 근거 확인이나 사용자 결정을 요청한다.
- 최종 보고에는 두 트랙의 식별자(Agent id / Run·Task·dispatch id)와 각 트랙이 실제로 확인한
  근거(file:line)를 함께 남긴다 — "두 모델이 동의했다"는 것 자체가 근거가 아니라, 각 트랙이 무엇을
  직접 봤는지가 근거다.

## 다루지 않는 것

- Orca/codex 실행 메커니즘 자체 — `orca-codex-delegate` skill 참조.
- "고위험 판단" 기준 — 각 프로젝트 CLAUDE.md가 정의한다.
- 세 개 이상 트랙으로 확장하는 패턴(예: judge panel) — 필요하면 `Workflow` 도구(사용자가 명시적으로
  다중 에이전트 오케스트레이션을 요청했을 때만)를 고려한다.
