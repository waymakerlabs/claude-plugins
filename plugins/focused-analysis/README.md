# focused-analysis

어려운 진단성 질문("이게 정상인가 결함인가", "근본 원인이 뭔가")에 대해 **Opus 서브에이전트**와
**codex CLI 직접 실행**을 동시에 독립 실행해 교차검증한 뒤, Claude가 두 결과를 종합해 최종
판단을 내리는 skill입니다. 별도의 오케스트레이션 앱이나 다른 플러그인 없이 `codex` 명령만 있으면
동작합니다.

## 스킬

| 스킬 | 설명 |
|------|------|
| `focused-analysis` | Opus 서브에이전트 트랙 + codex CLI 트랙을 동시에 실행하고, 둘 다 완료된 뒤에만(barrier) 종합 판단을 내리는 절차. 자동 매칭 트리거: "집중 분석해줘", "상세 분석해줘" 같은 강조된 분석 요청. |

## 다루는 것

- **이중 트랙 동시 실행** — `Agent` 도구(model: opus)와 `codex exec`(읽기 전용 샌드박스, 모델·effort
  명령줄 고정, Bash 백그라운드 실행)를 같은 메시지에서 병렬로 시작.
- **barrier 종합** — 하나만 도착해도 종합하지 않고 둘 다 기다린 뒤, 일치/불일치 지점을 명시적으로
  구분해 보고.
- **codex 실패 폴백** — 1회 재시도 후에도 실패하면 Opus 서브에이전트 리뷰로 대신하고 그 사실을 보고에 명시.
- 강조 없는 일반 분석 요청과의 경계 — 매번 쓰면 비용이 2배이므로, 트리거 문구가 명확할 때만 발동.

## 다루지 않는 것

- 3개 이상 트랙으로 확장하는 judge-panel류 패턴 — 그건 `Workflow` 도구(사용자의 명시적 다중 에이전트
  오케스트레이션 요청이 있을 때)의 영역입니다.

## 설치

```bash
/plugin install focused-analysis@waymakerlabs-claude-plugins
```

## 요구사항

- Codex CLI 설치 및 인증 (`codex` 명령이 PATH에 있고 로그인되어 있어야 합니다)
- `~/.codex/config.toml`의 `model`이 스킬이 쓰는 모델(`gpt-6.1-sol`)과 일치하는지 실행 전 확인
